# Annotation guide skeleton

## Purpose

Label whether each candidate is a message, nomenclature, procedural language, biographical language,
or private-person material. Group publications into document families based on shared document text.
This file is a skeleton. No corpus annotation is part of W10.

## Independent pass

Each candidate receives two independent annotations. Annotators must not see the other annotation.
Use the annotation schema in this directory. Record one class and one family ID for every item.

## Class labels

- Message: substantive political meaning that may appear on message surfaces.
- Nomenclature: an official name or title. It is not a message finding.
- Procedural: legislative, publication, or office process language.
- Biographical: language about a person's life history or role history.
- Private: material held by the Article XIII privacy floor.

## Family labels

Assign one family ID to publications that reuse the same document with local edits. Do not join an
A-B-C chain when the first and third documents are not sufficiently alike. A joint release is one
family even when many offices publish it.

## Adjudication

Exact agreement requires no adjudicator. Any class or family disagreement requires a separate
decision that records the adjudicator ID. Unresolved items do not enter metrics.

## Split discipline

The harness assigns train, validation, and test splits by date. Do not move examples across split
boundaries after reading their labels.
